# Vault – agent instructions

Personal Obsidian vault. Keep the language of the original text; the vault may mix languages.

## Vault structure

| Path | Purpose |
|---|---|
| `Quick notes.md` | Inbox. Lines like `- DD-MM-YYYY HH:mm – text`. Meant to be sorted to the right place and then emptied |
| `Braindump.md` | Loose notes, learnings, test data, config problems, API info |
| `Reminders/To do.md` | All tasks (Tasks plugin syntax) |
| `Reminders/DD-MM-YYYY.md` | Notes for a specific date, linked back to `[[To do]]` |
| `Team/Stand-up/DD-MM-YYYY.md` | Optional. Stand-up notes (template: `Templates/Stand-up.md`) |
| `Team/Refinement/DD-MM-YYYY.md` | Optional. Refinement notes (template: `Templates/Refinement.md`) |
| `Meetings/DD-MM-YYYY Title.md` | Optional. Meeting notes (template: `Templates/Meeting.md`) |
| `Jira.md` | Generated by `Scripts/refresh-jira.sh`. Do not edit |
| `Pull requests.md` | Generated by `Scripts/refresh-prs.sh`. Do not edit |
| `Dashboard.md` | Dataviewjs dashboard. Do not edit unless asked |
| `Templates/` | Templater templates. Do not edit unless asked |

## Conventions

- Dates in file names and headings: `DD-MM-YYYY`. Frontmatter dates: `YYYY-MM-DD`.
- Notes start with `# <emoji> <Kind> – DD-MM-YYYY`, then a `Back to [[Hub]]` link. Match the matching template.
- Tasks use Tasks-plugin syntax: `- [ ] text`, optional `📅 YYYY-MM-DD`, priority emoji, `✅ YYYY-MM-DD` when done. Every note should be reachable from a hub note (no orphans) via a `Back to [[...]]` link or a link from the hub.
- Indent with tabs for nested bullets. Use Obsidian wikilinks for internal notes.
- Do not create markdown files for planning or tracking.

## Cleanup (`/cleanup`)

Goal: tidy recent notes so they are formatted consistently, grouped sensibly, and in the right place.

**Scope:** files modified in the last 7 days (check with `git status`/`git log`/file mtimes), plus `Quick notes.md`. Skip generated files, `Templates/`, `Dashboard.md`, `.obsidian/`, and `.smart-env/`.

**Allowed**
- Fix formatting: headers, frontmatter, back-links, bullet/indent style, spacing, blank lines, emoji headings that match the existing style.
- Fix obvious spelling and typos without changing meaning.
- Group related lines under headings.
- Mark things: turn clearly actionable lines into `- [ ]` tasks, link ticket keys and notes, add `[[links]]` to hubs so a note is not an orphan.
- Move items from `Quick notes.md` to the correct note (Braindump, To do, stand-up, refinement, meeting), then remove only the moved lines from Quick notes.
- Rename or create a note only when it follows a template/convention above.

**Never**
- Remove, shorten, summarise or merge away any information. Everything in the original must still be present afterwards (moving and re-wording only for typos is OK).
- Assume or add information: no guessed names, dates, owners, meanings of acronyms, ticket titles, deadlines, status, or participants. Do not fill gaps from memory or from the web.
- Translate between languages.
- Mark a task as done, set a due date, or change an existing task's meaning.
- Touch secrets or token values (leave them, but warn if found in plain text).
- Commit, push, or delete files. Leave changes unstaged for review (new files may be `git add`ed).

**Ask first** (use the ask-user tool, list all questions together, wait for answers) whenever:
- A line could belong in more than one place, or its place is unclear.
- Wording is ambiguous, a name/term is unclear or looks like a typo you are not sure about.
- A line could be a task but it is unclear whether it is one, or who owns it.
- Something needs a date, owner, ticket, or any other fact that is not in the note.
- Anything would be removed, merged or restructured beyond formatting.

**Procedure**
1. List the files in scope and read them fully.
2. Make a plan of the proposed changes per file. If there are any questions, ask them before editing.
3. Apply only the approved/unambiguous changes.
4. Verify nothing was lost: compare `git diff` against the originals and confirm every original piece of information still exists.
5. Report briefly: files changed, what was moved/marked, and anything left untouched or still open as a question.
